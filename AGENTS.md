# AGENTS.md

## Контекст проекта

Telegram-бот «Карманный финсоветник» для планирования личных финансов.
Показывает будущее денег: свободный остаток, ближайшие платежи, цели, советы.

Публичное имя бота — «Карманный финсоветник» (используется в `/start` и текстах бота).

**Главный документ:** `PRD.md` в корне проекта. Всегда читай его перед началом работы.
Если задача не описана в PRD — спроси, прежде чем делать.

## Стек

- Python 3.12+
- aiogram 3.x
- SQLite (MVP), PostgreSQL (позже)
- Конфиг: python-dotenv (`.env`)
- Хостинг: VPS в РФ
- LLM для советов: API (Фаза 6)
- Тесты: pytest, линтер: ruff

## Команды

```bash
source .venv/bin/activate       # активация окружения
pip install -r requirements.txt # зависимости
python bot.py                   # запуск бота
pytest                          # тесты
ruff check .                    # линтер
python -m py_compile bot.py     # проверка синтаксиса
```

## Правила кода

Python 3.12+, async/await для всего I/O.
Типизация обязательна для публичных функций.
snake_case для функций, PascalCase для классов.
БД — только асинхронные вызовы. Никаких синхронных запросов в хендлерах.
Секреты и настройки — только через `config.py` и `.env`; токен не хардкодить.
Роутеры собираются функциями `build_router()` в `handlers/` (чтобы диспетчер можно было пересоздавать в тестах).
Бизнес-логика — в `services/` (чистые функции и репозитории), хендлеры тонкие.
Тесты — pytest + pytest-asyncio, БД для тестов — in-memory SQLite.

## Работа с БД

ORM — SQLAlchemy 2.0 async + aiosqlite. Движок и фабрика сессий живут в классе `Database` (`models/database.py`); сессия внедряется в хендлеры через middleware. Глобальных соединений нет.
Суммы хранятся целыми рублями (`INTEGER`).
Таблицы: users, transactions, debts, goals.
Профиль Фазы 1 живёт в `users`: `free_money`, `income_type` (`fixed`/`irregular`), `income_dates` (JSON вида `[{"day": 10, "amount": 50000}]`), `income` (средний доход).
`transactions` (Фаза 2): `telegram_id`, `type = expense | income | correction`, `amount` (целые рубли), `created_at` (TEXT, ISO). Без категорий.
`debts` (Фаза 3): `telegram_id`, `name`, `type = loan | mortgage | credit_card | installment`, `amount` (целые рубли), `payment_day` (1–31), `created_at` (TEXT, ISO). Без остатка долга и грейс-периода.
Формула Фазы 2: свободные деньги = `users.free_money`; `/minus` уменьшает его, `/plus` увеличивает, `/correct` задаёт новое значение — все пишут операцию в `transactions`.
Команды операций: `/minus [сумма]`, `/plus [сумма]`, `/correct [сумма]`. Без аргумента — ForceReply и приём следующего сообщения как суммы. Знак зашит в команду.
Операции с `debts` — асинхронные функции в `services/debts_repo.py`.
Операции с `transactions` — асинхронные функции в `services/transactions_repo.py` (модели — только ORM).
Изменение схемы: `create_all` не меняет существующие таблицы — при смене полей удаляй dev-БД `finance.db`.

## Логика расчётов

Свободные деньги = `users.free_money` (Фаза 2: меняется через `/minus` и `/correct`, растёт от `/plus`).
Обязательные платежи (Фаза 3) уменьшают «Свободно до ЗП» и «Свободно до конца месяца» на `/stats`.
Прогноз — на основе средних трат за последние N дней (Фаза 4).
Если покупка ломает план — предупредить, но не запрещать.
